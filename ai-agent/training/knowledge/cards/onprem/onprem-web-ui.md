For the others pskit starts a **companion** UI next to the service, on a private Docker network with it, listening on the same interface as the service: | Service | Companion | Default port | Login | |---|---|---|---| | PostgreSQL, MySQL, MariaDB | Adminer | 8089 | the database user and password (server filled in) | | Redis, Valkey, KeyDB, Dragonfly | Redis Commander | 8082 | `admin` + a generated password (`PSKIT_<KEY>_GUI_PASSWORD`) | | Kafka (Redpanda), Apache Kafka | Kafka UI | 8088 | `admin` + a generated password (sign-in page `/auth`) | | MongoDB | Mongo Express | 8081 | the MongoDB user and password | A second UI of the same kind on one server takes the next free port (8083, 8084, ...); *Details* shows the real one. Start it with *Also start the web UI* when creating, *Details / Add web UI*, or the CLI: Azurite has no web UI: attach **Azure Storage Explorer** (desktop) with the connection string from the env file.
### With or without a password The create form's **Web UI login** (and *Details / Add web UI*)

chooses how the companion UI signs in: | Choice | Redis Commander, Kafka UI | Mongo Express | Adminer | |---|---|---|---| | **With password** (default) | user `admin`, a generated password, or yours | the MongoDB login, or `<user>` + yours | the database login (always) | | **Without password** | open (`HTTP_USER` unset, `AUTH_TYPE=DISABLED`) | open (`ME_CONFIG_BASICAUTH=false`) | not offered | Your own or a generated password goes to the env file as `PSKIT_<KEY>_GUI_PASSWORD` and shows in *How to use*. Without a password, anyone who reaches the port can use the UI, and the UI holds the service's credentials. Use it on `127.0.0.1`, on a private network, with the port open only to your IP, or keep the port closed and use the tunnel. pskit prints a warning when a UI without login listens on `0.0.0.0`. Built-in UIs keep their own sign-in: RabbitMQ, LavinMQ, MinIO and RustFS use the service's user and password; ElasticMQ, NATS monitoring and Mailpit have none.
