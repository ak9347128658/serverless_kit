## Databases: one server, or a primary with read replicas - **Single server**: one

container on this machine or a server. To scale it up, give that server more CPU and memory (vertical scaling). Nothing else changes. - **Primary + read replicas** (horizontal scaling): the **primary** takes every write, each **read replica** on another server keeps a copy and answers reads, and an optional **load balancer** gives the functions one address that sends writes to the primary and reads to the replicas. Add replicas later as reads grow. You only pick the servers: which one writes (the primary), which ones read (the replicas) and which one runs the load balancer. Save them first (**Servers**, below). pskit installs Docker where it is missing and sets up replication for each engine: | Engine | Replication | *Synchronous* means | Load balancer (one address) | |---|---|---|---| | PostgreSQL | streaming replication (WAL), each replica starts from `pg_basebackup` | `synchronous_standby_names = 'ANY 1 (*)'`: a commit waits until one replica has it on disk | pgpool-II, port 6432 | | MySQL | GTID replication; a replica copies the databases, then follows | semi-synchronous: a commit waits for one replica (async again after 10 s without one) | ProxySQL, port 6033 | | MariaDB | GTID replication, as MySQL | built-in semi-synchronous, as MySQL | ProxySQL, port 6033 | | MongoDB | replica set (`rs_<key>`), members share a generated key file | write concern `w: majority` | none: the driver routes from one replica set URL | **Asynchronous** (default) is the fastest: the primary commits at once and replicas follow a few milliseconds behind, so a crash of the primary can lose the last writes. **Synchronous** loses no committed write, at the cost of a round trip to a replica per commit. PostgreSQL waits while no replica is connected, so keep at least two replicas with *sync*. The load balancer sends writes, transactions and `SELECT ... FOR UPDATE` to the primary and plain reads to the replicas, and falls back to the primary only when no replica is up. Without a load balancer, the functions' `URL` is the primary and the replicas are listed in `READ_URLS`. The form draws the result as you pick (functions → load balancer → primary → replicas, solid lines for sync, moving dashes for async). **Details** shows the same picture with each member's state, every replica's lag, what the primary reports (`pg_stat_replication`, `SHOW REPLICAS`, `rs.status()`), and **+ Add read replica** / **Remove**.
