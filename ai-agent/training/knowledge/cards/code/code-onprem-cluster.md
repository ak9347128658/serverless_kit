# Code: On-premises cluster and network modules

The deploy pipeline in the architecture doc is pskit.yml, then the config loader, the schema, the project, provider validate, the packaging builder, provider render to main.tf.json, the Terraform runner, deployment.json, and the dashboard. The runtime path is platform, shim, adapter, dispatch.execute, handler. runtime/ is stdlib-only and stays on Python 3.9. Terraform is built as Python dicts. Zip artifacts are byte-reproducible.

`src/py_serverless_kit/core/onprem_balancers.py`: Named load balancers: one saved server running OpenResty that many projects and clusters share by path. `src/py_serverless_kit/core/onprem_cluster.py`: Scaling clusters for on-prem functions: Docker Swarm, Kubernetes (k3s) or HashiCorp Nomad on saved SSH servers. `src/py_serverless_kit/core/onprem_cluster_scripts.py`: Shell scripts and workload manifests for on-prem scaling clusters (Docker Swarm, Kubernetes via k3s, Nomad). `src/py_serverless_kit/core/onprem_control.py`: Talk to a deployed on-premises host's control API (``/__pskit/...``). `src/py_serverless_kit/core/onprem_follow.py`: On-prem services follow the functions when they move (``pskit deploy`` to another server or cluster, or after `src/py_serverless_kit/core/onprem_lb.py`: Load balancing algorithms and the OpenResty (nginx + Lua) config pskit writes for them. `src/py_serverless_kit/core/onprem_network.py`: The firewall rules on-prem servers need, with their real names and addresses (docs/onprem-network.md). `src/py_serverless_kit/core/onprem_placement.py`: Function placement on premises: groups of functions on different servers (or clusters), one project. `src/py_serverless_kit/core/onprem_usage.py`: Where each saved on-prem server is used, how the machines connect, and which functions really use a resource.
