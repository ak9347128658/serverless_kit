# Node.js / TypeScript runtime: design contract Maintainer document

. It fixes the interfaces between the parts of the Node.js support so they can be built and changed independently. User documentation lives in `docs/nodejs.md`.
## Language selection * A service is **either Python or Node.js**, chosen by

`provider.runtime`: `python3.9`..`python3.14` or `nodejs18`, `nodejs20`, `nodejs22`, `nodejs24` (`config.schema.NODE_RUNTIMES`, `runtime_language()`, `ServiceConfig.language`). A function may pin another runtime of the same language only. * TypeScript is Node.js plus a compile step (`package.node.typescript`, auto-detected). * Providers declare `node_runtimes = {"nodejs20": "<platform id>", ...}`. Empty = no Node.js (validation then reports `... does not support Node.js functions in pskit yet`). `Provider.runtime_id()` maps either language; `default_runtime_for("node")` picks nodejs20 or the nearest. * `node_vendor_dependencies` (default True): npm-install production dependencies into the bundle. False where the platform installs from `package.json` itself (GCP, Azure). * `node_bundle` (default False): the platform needs one self-contained file per entry (esbuild), e.g. Cloudflare Workers.
## Handlers Same string as Python: `module.function` (or `module:function`)

. The module path uses dots for folders and is resolved against the bundle root: `src.handlers.hello` → `src/handlers.{js,mjs,cjs}` (TypeScript `src/handlers.ts` is compiled to `src/handlers.js` before packaging), or `src/handlers/index.js`. ## Bundle layout (Node.js)

Shims only `require("./pskit_runtime/adapters/<cloud>")` and re-export the platform entrypoint. The zip must stay byte-reproducible (the builder already sorts entries and fixes timestamps; npm output must not add timestamps: use `--no-audit --no-fund --ignore-scripts`, and keep `package-lock.json` when present).
