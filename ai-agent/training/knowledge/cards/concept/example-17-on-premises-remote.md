# Example: 17-on-premises-remote

This directory is one of the examples that tests/test_examples.py packages and runs locally because it contains pskit.yml. Files here include README.md, pskit.yml, requirements.txt. Comments in pskit.yml: Remote on-premises deploy. This file ships the function bundle to a Linux server that may not have Python. `python: bundle` downloads a portable CPython at apply time and copies it with the app. `install: systemd` keeps the host up across reboots. Required on the laptop: OpenSSH (`ssh`, `scp`). Required on the server: SSH access. Python on the server is optional. set PSKIT_ONPREM_HOST=192.0.2.10 pskit deploy Switch to Docker (image built on this machine, run on the server) by replacing deploy.method with docker and setting pem to the server .pem. pskit deploy asks for a .pem on a terminal when identity_file is empty (Enter keeps the SSH agent for method ssh). method: scp is the same archive copy as ssh. Docker on a server installs the engine when `docker` is missing, then waits until /__pskit/health answers. See the README.
# 17 · On-premises, remote server

Example 16 runs the host on the laptop that runs `pskit deploy`. This example copies the same kind of host onto a machine you SSH into — a factory box, a VM, or a rack server. The handler code does not change. Three ways to get code from this laptop onto that server: | `options.deploy.method` | What the server needs | What the laptop needs | When to use it | | --- | --- | --- | --- | | `local` | this machine (example 16) | Python + pskit | laptop / the server *is* the deploy machine | | `ssh` or `scp` | SSH. Python only if `python: system` | OpenSSH (`ssh`, `scp`) and a `.pem` or the SSH agent | most on-prem Linux boxes | | `docker` | SSH. Docker is installed at deploy when it is missing | Docker CLI, OpenSSH, and a `.pem` for the server | the server should run a container, with or without Docker already installed | When the server has **no Python**, pick one of: - `method: ssh` (or `method: scp`) and `python: bundle` — pskit downloads a portable CPython (python-build-standalone) at apply time, packs it into one `release.tar.gz`, copies that file, and restarts systemd (this file) - `method: docker` — the image is `FROM python:3.12-slim` and is built on this machine. The server does not need Python.
