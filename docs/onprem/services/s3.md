# Amazon S3 compatible server (Python / Node.js)

Search terms: Amazon S3 compatible, pskit S3 server, s3-node, SigV4, presigned URL, versioning, multipart upload, S3
console, bucket

pskit ships its own Amazon S3 compatible server, in two flavors: **Amazon S3 compatible (Python)** (`--service s3`)
and **Amazon S3 compatible (Node.js)** (`--service s3-node`). Both answer the S3 API with SigV4 authentication: the
service's user is the access key ID and its password is the secret access key. They support versioning, multipart
uploads, presigned URLs, policies, CORS, lifecycle rules, object lock and website hosting, and have a web console at
`/ui/`. This page covers creating it and using it as a resource; the API coverage, the Python and Node.js
implementations and boto3 / AWS SDK examples are in [the S3 compatible server reference](../aws-compatible/s3.md).

## Amazon S3 compatible at a glance

The Amazon S3 compatible service in the on-prem catalog has these settings (read from `core/onprem_services.py`):

| | |
|---|---|
| `--service` | `s3` / `s3-node` |
| Studio card | **Object storage** > **Amazon S3 compatible (Python)** / **Amazon S3 compatible (Node.js)** |
| Docker image | `python:3.12-alpine` / `node:22-alpine` |
| Port | `9000` |
| Use as | `storage` (Bucket, resource type `storage`) |
| Login | user (default `pskit`) and password (generated when empty) |
| Data | kept in `/data` (a Docker volume, or `<data_dir>/<container>` on a server with a data directory) |
| Backup | yes (`.tar.gz`) |
| Web UI | S3 console on port `9000` at `/ui/` (the service's user and password) |
| Console | aws s3 (helper) |

## Create Amazon S3 compatible in studio

The studio creates Amazon S3 compatible from the *Resources* page, with a form that checks every field before it
starts:

1. Open the **Resources** page in the sidebar.
2. Click **+ On-prem service** in the page header (or **+ Create service** in the *On-prem services* card lower on the
   page).
3. In the *Create a service* drawer, under **Object storage**, click the **Amazon S3 compatible (Python)** or **Amazon
   S3 compatible (Node.js)** card. The drawer title changes to *Create Amazon S3 compatible (Python)*.
4. **Resource key**: type `files` (the form suggests a free name). Handlers and triggers use this key.
5. **Where**: **This machine** (Docker here), or **One SSH server** and pick a saved server in **Server** (or *New
   connection…* and type Host, User, SSH port and *Log in with*), or **Scaling cluster** to run it on one server of a
   cluster.
6. **Port**: leave empty for `9000`, or type another one if that port is taken.
7. **Security**: **User** (empty = default), **Password** (empty = generated; **Generate** and **Show** help),
   **Listen on**: *This machine only (127.0.0.1)* or *Network (0.0.0.0)*.
8. **Web UI**: built in (S3 console); *How to use* shows its address and login.
9. **Trigger functions**: tick the functions that run for each message / object. Each gets an event on `resource:
   files`.
10. **Advanced** (optional): **Address functions use** (default: the SSH host, or 127.0.0.1 here) and **Docker
    image**.
11. Click **Create**. The job log streams below the form (Docker is installed on an SSH server when missing, the image
    is pulled, the container started and checked). The button turns into *Created*.
12. The resource and the triggers are added to the draft. Click **Save** in the top bar to write `pskit.yml`, then
    deploy.

## Create Amazon S3 compatible from the terminal

`pskit resources onprem create KEY --service s3` starts Amazon S3 compatible and prints the `pskit.yml` entry; add
`--save` to write it into `pskit.yml` (comments in the file are not kept). Without `--ssh`, `--server`, `--cluster` or
`--local` it goes where the functions deploy (`provider.options.cluster`, then `provider.options.deploy`), else this
machine.

```bash
pskit resources onprem create files --service s3 --attach worker --save                 # here, or the deploy target
pskit resources onprem create files --service s3-node --attach worker --save                 # here, or the deploy target
pskit resources onprem create files --service s3 --server edge1 --attach worker --save   # a saved server
pskit resources onprem create files --service s3 --ssh ubuntu@10.0.0.5 --pem ~/.ssh/key.pem --save
export FILES_PASSWORD='Str0ng.pass-1'
pskit resources onprem create files --service s3 --user app --password-env FILES_PASSWORD --bind 127.0.0.1 --local --save
```

- `-a / --attach FUNCTION` (repeatable) adds the trigger to that function.
- `--port`, `--image`, `--address`, `--bind` and `--sudo` change the defaults; see `pskit resources onprem create
  --help`.

## What pskit writes for Amazon S3 compatible

Creating Amazon S3 compatible adds a resource to `pskit.yml` and, when there are credentials, writes them to the
on-prem env file (`provider.options.env_file`, default `.env.onprem`), never into `pskit.yml`. The examples use
address `10.0.0.5` and the defaults.

```yaml
resources:
  files:
    type: storage
    external: true
    options:
      driver: s3
      endpoint: http://10.0.0.5:9000
      bucket: files
      region: us-east-1
      access_key_env: PSKIT_FILES_ACCESS_KEY
      secret_key_env: PSKIT_FILES_SECRET_KEY
      path_style: true
      create_bucket: true
    connection:
      console_url: http://10.0.0.5:9000/ui/
      url_env: PSKIT_FILES_URL
```

```text
# .env.onprem
PSKIT_FILES_ACCESS_KEY=pskit
PSKIT_FILES_SECRET_KEY=<password>
PSKIT_FILES_URL=http://10.0.0.5:9000
```

When the main provider is not `onprem`, the resource goes under `providers.onprem.resources` so the other clouds are
not affected. Created services are recorded in `.pskit/onprem-services.json`.

## Use Amazon S3 compatible from a handler

A handler reaches Amazon S3 compatible through `resource("files")`, which returns the connection values pskit passes
to bound functions; a value ending in `_env` is the **name** of a variable from the env file, read with
`ctx.env[...]`.

As a bucket, functions with `storage: {resource: files}` run for each new or deleted object, and `put_object` writes
through the on-prem host:

```python
from py_serverless_kit import resource
from py_serverless_kit.runtime.onprem_host import put_object


def upload(event, ctx):
    """HTTP trigger: write one object into the files bucket."""
    put_object(resource("files").native_name, "in/hello.txt", b"hello")
    return {"written": "in/hello.txt"}


def on_file(event, ctx):
    """Trigger: storage: {resource: files}."""
    for record in event.records:
        ctx.logger.info("object", extra={"bucket": record.bucket, "key": record.key,
                                          "action": record.action, "size": record.size})
```

```yaml
functions:
  upload:
    handler: app.handlers.upload
    events:
      - http: POST /upload
  on-file:
    handler: app.handlers.on_file
    events:
      - storage: {resource: files}
```

`pskit resources usage files` (studio: **How to use** on the resource row) prints the same code for Python and Node.js
with the libraries to install, and `pskit resources onprem usage files` shows how to connect from any other program.

## Open the Amazon S3 compatible web UI, console and terminal

The Amazon S3 compatible row in the *On-prem services* card (Resources page) has these buttons:

- **Details** shows the state, the endpoint and **Open ...** links for: S3 console on port `9000` at `/ui/` (the
  service's user and password). **Check web UI** finds out why a UI does not open (container, port, firewall).
- **Browse** opens pskit's own browser (buckets and objects over S3).
- **Console** runs one command at a time with **aws s3 (helper)** and the service's credentials, for example `s3 ls`,
  `s3api list-buckets`, `s3 ls s3://files --recursive`. Switch to *Shell in the container* for `sh`.
- **Terminal** opens a full terminal in the browser (ttyd in Docker on this machine): `sh` in the container.

```bash
pskit resources onprem status files --reveal      # state, health, endpoint, credentials
pskit resources onprem usage files                # connect from any program
pskit resources onprem logs files -n 100
pskit resources onprem gui files                  # print the web UI links (starts a companion)
pskit resources onprem gui files --check
pskit resources onprem console files "s3 ls"
pskit resources onprem terminal files
pskit resources onprem tunnel files                # firewalled port: reach it on 127.0.0.1
```

More: [terminal and software](../terminal-and-software.md).

## Back up and remove Amazon S3 compatible

Amazon S3 compatible backups stream a dump out of the container into `.pskit/backups/files-<time>.tar.gz` on this
machine (also from an SSH server). In studio: **Backup** on the row, *Save to folder* (empty = `.pskit/backups`),
**Back up now**.

```bash
pskit resources onprem backup files
pskit resources onprem backup files --dir ~/backups
```

To remove Amazon S3 compatible: **Remove** on the row, then **Remove, keep data** or **Delete data too**. The
container is deleted, its variables leave the env file, and the resource and its triggers leave the draft (click
**Save**). On the Resources table, **Delete** on the resource offers *pskit.yml only*, *Stop service, keep data* or
*Delete service and data*.

```bash
pskit resources onprem remove files --save                 # keep the data volume
pskit resources onprem remove files --delete-data --save   # delete it too
```

A kept volume is reused when you create the service again with the same key (to change the password, remove with *keep
data* and create it again with the new password).
