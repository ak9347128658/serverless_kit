# Amazon S3 compatible server (s3, s3-node)

Search terms: S3 compatible server, self-hosted S3, s3-node, boto3 endpoint_url, forcePathStyle, path-style addressing,
aws --endpoint-url, presigned URL, S3 console, bucket on premises, SignatureDoesNotMatch, MinIO alternative

The Amazon S3 compatible server is pskit's own implementation of the Amazon S3 API, in the repository folder `aws/s3`
(`python/server.py` and `nodejs/server.js`, both with the console page `ui/index.html`). boto3, the AWS SDKs, the AWS
CLI (`aws s3` and `aws s3api`), rclone, s3cmd and pskit's `s3` storage driver work with it unchanged once they point at
its endpoint and sign with a key it knows. This page covers creating it, its web console and its clients. The full
list of operations, settings and error codes is in [s3-api-reference.md](s3-api-reference.md).

## S3 compatible server at a glance

The Amazon S3 compatible server has these properties (from `core/onprem_s3.py` and the server code):

| | |
|---|---|
| pskit service | `s3` (Python) or `s3-node` (Node.js), interchangeable |
| Port | `9000` |
| Authentication | AWS Signature Version 4 (header, presigned URL, `aws-chunked` streaming, POST policy) and Version 2 |
| Access key ID / secret key | the service's *User* (default `pskit`) / *Password* |
| Region | any region name is accepted for signing; buckets report `us-east-1` unless created with a location |
| Addressing | path-style (`http://host:9000/bucket/key`) always; virtual-hosted style only for names under `S3_DOMAIN` |
| Web console | `http://<address>:<port>/ui/` |
| Health | `GET /-/health` (no auth) |
| Data | `/data` in the container: one file per object version, plain (not encrypted at rest) |
| Not supported | S3 Select, torrents, S3 Express directory buckets, access points |

## Create the S3 server in studio

The S3 server is created from the *Resources* page in studio:

1. Open **Resources** in the sidebar.
2. Click **+ On-prem service** in the page header (or **+ Create service** in the *On-prem services* card lower on the
   page). The *Create a service* drawer opens.
3. Under **Object storage**, click **Amazon S3 compatible (Python)** or **Amazon S3 compatible (Node.js)**.
4. **Resource key**: the form suggests `files`. Handlers and triggers use this name; the bucket gets the same name
   (made S3-safe: lower case, `-` for other characters).
5. **Use as**: *Bucket* (the only choice).
6. **Where**: *This machine*, *One SSH server* (pick a saved server under **Server**, or type **Host**, **User**,
   **SSH port** and **Log in with**), or *Scaling cluster*.
7. **Port**: empty means `9000`. Set another one when MinIO, RustFS or a second S3 server already uses 9000 there.
8. **Security**: **User** becomes the access key ID (empty: `pskit`); **Password** becomes the secret access key (empty:
   generated; **Generate** fills one in, **Show** shows it). **Listen on**: `127.0.0.1` (only that machine) or
   `0.0.0.0` (other servers too).
9. **Web UI** shows *S3 console*: it is built in, nothing to start.
10. **Trigger functions**: tick the functions that should run when a file is created or deleted in the bucket.
11. Optional, under **Advanced**: **Address functions use** and **Docker image**.
12. Click **Create**. The log shows `docker create`, the copy into `/app` and `docker start`; the button reads
    *Created* when the server is healthy.

After it is created, the service is a row in the *On-prem services* table, and a toast says the resource was added to
`pskit.yml` (not saved yet). Click **Save** in the top bar (or press Ctrl+S) to write `pskit.yml`.

## Create the S3 server from the terminal

The S3 server is created with `pskit resources onprem create`:

```bash
pskit resources onprem create files --service s3 --save                              # Python, this machine
pskit resources onprem create files --service s3-node --server edge1 --save          # Node.js, a saved SSH server
pskit resources onprem create files --service s3 --user AKIAPROD --password-env S3_PW --attach ingest --save
pskit resources onprem create media --service s3 --port 9100 --save                  # 9000 already taken
```

| Option | Effect for the S3 server |
|---|---|
| `--service s3` / `s3-node` | Python or Node.js implementation |
| `--user` | access key ID (default `pskit`) |
| `--password` / `--password-env` | secret access key (default: generated). Prefer `--password-env` |
| `--port` | published port (default 9000) |
| `--bind` | interface (default `127.0.0.1` here, `0.0.0.0` over SSH) |
| `--ssh`, `--pem`, `--server`, `--cluster` | where it runs (see [../servers.md](../servers.md)) |
| `-a, --attach FN` | add a storage trigger on function `FN` (repeatable) |
| `--save` | write the resource (and triggers) into `pskit.yml` |

Then check it and print the connection details:

```bash
pskit resources onprem status files              # state, health, endpoint, console link
pskit resources onprem usage files --reveal      # endpoint, keys and code snippets for any program
pskit resources onprem console files "s3 ls"     # the AWS CLI in a helper container (amazon/aws-cli)
pskit resources onprem backup files              # .tar.gz of /data into .pskit/backups
```

## What the S3 server adds to pskit.yml and the env file

Creating the S3 server with `--save` (or the studio's automatic add) writes a `storage` resource on pskit's `s3`
driver. For key `files` on this machine:

```yaml
provider:
  name: onprem
  options:
    env_file: .env.onprem

resources:
  files:
    type: storage
    external: true
    options:
      driver: s3
      endpoint: http://127.0.0.1:9000
      bucket: files
      region: us-east-1
      access_key_env: PSKIT_FILES_ACCESS_KEY
      secret_key_env: PSKIT_FILES_SECRET_KEY
      path_style: true
      create_bucket: true          # the bucket is created on first use
    connection:
      console_url: http://127.0.0.1:9000/ui/
      url_env: PSKIT_FILES_URL

functions:
  ingest:
    handler: app.handlers.ingest
    events:
      - storage: {resource: files}  # from --attach ingest / Trigger functions
```

When the main provider is not `onprem`, the same block goes under `providers.onprem` so other clouds are unaffected.
The keys go to `.env.onprem` as `PSKIT_FILES_ACCESS_KEY`, `PSKIT_FILES_SECRET_KEY` and `PSKIT_FILES_URL`. When the key
is not a valid bucket name (for example `my_Files`), the resource also gets `name: my-files`.

## Open the S3 web console

The S3 web console is a page served by the server itself at `/ui/` (on both implementations). To open it:

- **In studio**: *Resources* > *On-prem services* card > **Details** on the service row > **Web UI** > **Open S3
  console**. *Check web UI* finds out why it does not open (container, port, firewall, bind).
- **From the terminal**: `pskit resources onprem status files` prints the link; open
  `http://<address>:<port>/ui/` in a browser. A browser that opens `/` is redirected to `/ui/`.

Sign in with **Access key ID** (the service's user) and **Secret access key (password)**. What the console does:

- Buckets: create (with versioning or object lock), delete (optionally emptying it first), and every bucket setting:
  versioning, tags, default encryption, website hosting, object lock, block public access (*Block all* makes the
  bucket private), bucket policy, object ownership, ACL, CORS, lifecycle (with *Run lifecycle now*), unfinished
  multipart uploads, replication, notifications, logging.
- Objects: browse folders, search, upload files and whole folders (drag and drop, with progress), create folders,
  download, preview images, video, audio and text, share links (presigned GET or PUT, 1 second to 7 days), copy, move
  and rename (also folders), delete, versions (download, delete, *Make current*, *Show deleted*), metadata and storage
  class, tags, ACLs, object lock retention and legal hold.

The session is an `HttpOnly`, `SameSite=Strict` cookie valid for 12 hours, and every console request carries a token
only the page knows. Ten failed sign-ins from one address lock that address out for five minutes.

## Browse the S3 server from studio without the console

Studio also has its own browser for the S3 server (it works the same on MinIO, RustFS and LocalStack):

1. *Resources* > *On-prem services* card > **Browse** on the service row. The *Browse files* drawer opens.
2. Pick a **Bucket**, or type a name and click **+ Create bucket**.
3. Use **Upload files**, **+ Folder**, **Refresh**, and per object **Download**, **Info**, **Rename / move**, **Copy**,
   **Delete** and **Share…** (link for 1 hour, 1 day, 7 days, or *link for…* a custom time; **Create link**).
4. **Bucket settings**: the versioning switch, **Make private**, **Make public (read)**, and *Bucket policy (JSON, the S3
   format)* with **Save policy**. **Delete bucket** removes it.

Uploads and downloads through the studio browser are limited to 64 MiB each; use the console or a client for bigger
files.

## Use the S3 server from boto3 (Python)

boto3 works with the S3 server when you give it the endpoint, a region and the keys. Use path-style addressing: the
default virtual-hosted style puts the bucket in the host name (`files.10.0.0.5`), which does not resolve.

```python
import os

import boto3
from botocore.config import Config

s3 = boto3.client(
    "s3",
    endpoint_url=os.environ["PSKIT_FILES_URL"],           # http://127.0.0.1:9000
    region_name="us-east-1",
    aws_access_key_id=os.environ["PSKIT_FILES_ACCESS_KEY"],
    aws_secret_access_key=os.environ["PSKIT_FILES_SECRET_KEY"],
    config=Config(s3={"addressing_style": "path"}),
)
s3.put_object(Bucket="files", Key="reports/today.txt", Body=b"hello", ContentType="text/plain")
print(s3.get_object(Bucket="files", Key="reports/today.txt")["Body"].read())
s3.upload_file("big.iso", "files", "isos/big.iso")                  # multipart above 8 MB
for page in s3.get_paginator("list_objects_v2").paginate(Bucket="files", Prefix="reports/"):
    for obj in page.get("Contents", []):
        print(obj["Key"], obj["Size"])
url = s3.generate_presigned_url("get_object", Params={"Bucket": "files", "Key": "reports/today.txt"}, ExpiresIn=3600)
```

The boto3 resource API works the same way:

```python
import os

import boto3
from botocore.config import Config

s3 = boto3.resource(
    "s3",
    endpoint_url=os.environ["PSKIT_FILES_URL"],
    region_name="us-east-1",
    aws_access_key_id=os.environ["PSKIT_FILES_ACCESS_KEY"],
    aws_secret_access_key=os.environ["PSKIT_FILES_SECRET_KEY"],
    config=Config(s3={"addressing_style": "path"}),
)
bucket = s3.Bucket("files")
bucket.put_object(Key="hello.txt", Body=b"hi")
for obj in bucket.objects.filter(Prefix="reports/"):
    print(obj.key, obj.size)
s3.BucketVersioning("files").enable()
```

## Use the S3 server from the AWS SDK for JavaScript v3

The AWS SDK for JavaScript v3 (`@aws-sdk/client-s3`) works with the S3 server with `endpoint`, `region`, the keys and
`forcePathStyle: true`:

```js
const { S3Client, PutObjectCommand, GetObjectCommand, ListObjectsV2Command } = require("@aws-sdk/client-s3");
const { getSignedUrl } = require("@aws-sdk/s3-request-presigner");

const s3 = new S3Client({
  endpoint: process.env.PSKIT_FILES_URL,       // http://127.0.0.1:9000
  region: "us-east-1",
  forcePathStyle: true,
  credentials: { accessKeyId: process.env.PSKIT_FILES_ACCESS_KEY, secretAccessKey: process.env.PSKIT_FILES_SECRET_KEY },
});

async function main() {
  await s3.send(new PutObjectCommand({ Bucket: "files", Key: "hello.txt", Body: "hi" }));
  const out = await s3.send(new GetObjectCommand({ Bucket: "files", Key: "hello.txt" }));
  console.log(await out.Body.transformToString());
  const list = await s3.send(new ListObjectsV2Command({ Bucket: "files" }));
  console.log((list.Contents || []).map((o) => o.Key));
  console.log(await getSignedUrl(s3, new GetObjectCommand({ Bucket: "files", Key: "hello.txt" }), { expiresIn: 600 }));
}
main();
```

## Use the S3 server from the AWS CLI

The AWS CLI works with the S3 server through `--endpoint-url`. Set the keys and a region in the environment:

```bash
export AWS_ACCESS_KEY_ID=pskit AWS_SECRET_ACCESS_KEY='<PSKIT_FILES_SECRET_KEY>' AWS_DEFAULT_REGION=us-east-1
aws --endpoint-url http://127.0.0.1:9000 s3 ls
aws --endpoint-url http://127.0.0.1:9000 s3 ls s3://files --recursive
aws --endpoint-url http://127.0.0.1:9000 s3 cp ./site s3://files/site --recursive
aws --endpoint-url http://127.0.0.1:9000 s3 sync ./site s3://files/site
aws --endpoint-url http://127.0.0.1:9000 s3api put-bucket-versioning --bucket files \
    --versioning-configuration Status=Enabled
aws --endpoint-url http://127.0.0.1:9000 s3api list-object-versions --bucket files
aws --endpoint-url http://127.0.0.1:9000 s3 presign s3://files/site/index.html --expires-in 3600
```

Without a local AWS CLI, `pskit resources onprem console files "<command>"` runs the same commands (without `aws` and
`--endpoint-url`) in an `amazon/aws-cli` helper container with the service's keys.

## Use the S3 server from a pskit handler

A pskit function uses the S3 server as a `storage` resource. A storage trigger runs the function when an object is
created or deleted (the host lists the bucket every `poll_seconds` and compares ETags; objects already there at the
first start are recorded, not emitted).

```python
import os

import boto3
from botocore.config import Config

from py_serverless_kit import resource
from py_serverless_kit.runtime.onprem_host import put_object

_s3 = boto3.client(
    "s3",
    endpoint_url=os.environ["PSKIT_FILES_URL"],
    region_name="us-east-1",
    aws_access_key_id=os.environ["PSKIT_FILES_ACCESS_KEY"],
    aws_secret_access_key=os.environ["PSKIT_FILES_SECRET_KEY"],
    config=Config(s3={"addressing_style": "path"}),
)


def ingest(event, ctx):
    bucket = resource("files").native_name
    for record in event.records:
        ctx.logger.info("file", extra={"bucket": record.bucket, "key": record.key, "action": record.action})
        if record.action == "created" and not record.key.startswith("done/"):
            body = _s3.get_object(Bucket=bucket, Key=record.key)["Body"].read()
            put_object(bucket, "done/" + record.key, body.upper())   # writes through the s3 driver
```

How the values reach the function:

- `PSKIT_FILES_URL`, `PSKIT_FILES_ACCESS_KEY` and `PSKIT_FILES_SECRET_KEY` come from the env file, which the on-prem
  host loads into its environment.
- `resource("files")` reads the `PSKIT_RESOURCE_FILES_*` variables pskit injects for the resource (type, name, and the
  `connection:` values such as `console_url`).
- `put_object` / `delete_object` from `py_serverless_kit.runtime.onprem_host` go through the resource's driver, so they
  need no client.

Add `boto3` to the function's requirements (see [../../functions/create.md](../../functions/create.md)). Node.js
handlers read the same environment variables with `@aws-sdk/client-s3` as shown above.

## Run the S3 server standalone with docker compose

The S3 server runs without pskit from the `aws/s3` folder. Build from that folder so the console page is included:

```bash
cd aws/s3

# docker compose: pick one of the two services (same port, same volume)
S3_SECRET_ACCESS_KEY='a-long-random-secret' docker compose up -d s3-python
S3_SECRET_ACCESS_KEY='a-long-random-secret' docker compose up -d s3-nodejs

# plain Docker
docker build -f python/Dockerfile -t pskit/s3:python .          # or nodejs/Dockerfile -> pskit/s3:nodejs
docker run -d --name s3 -p 127.0.0.1:9000:9000 -v s3-data:/data \
  -e S3_ACCESS_KEY_ID=AKIAPROD -e S3_SECRET_ACCESS_KEY='a-long-random-secret' pskit/s3:python

# no Docker at all (data in ./data)
S3_SECRET_ACCESS_KEY='a-long-random-secret' python python/server.py
S3_SECRET_ACCESS_KEY='a-long-random-secret' node nodejs/server.js
```

The compose file publishes `127.0.0.1:9000`, uses the volume `s3-data`, and reads `S3_ACCESS_KEY_ID` (default
`pskit`), `S3_SECRET_ACCESS_KEY` (required) and `S3_REGION` (default `us-east-1`). The images run as uid 10001 and
have a health check (`server.py --check` / `server.js --check`, which reads `/-/health`). The server refuses to start
without a credential unless `S3_AUTH=off`. All settings: [s3-api-reference.md](s3-api-reference.md#s3-server-settings).

## Troubleshoot the S3 server

| Symptom | Cause and fix |
|---|---|
| `SignatureDoesNotMatch` | The secret key is wrong, or a proxy changed the host, path or a signed header. Use the `PSKIT_<KEY>_SECRET_KEY` value; sign for the host and port the client actually connects to. |
| `InvalidAccessKeyId` | The access key ID is not the service's *User* (or one in `S3_CREDENTIALS`). |
| `RequestTimeTooSkewed` / `Request has expired` | The client's clock is more than 15 minutes off the server's, or a presigned URL expired. Sync clocks (NTP); presigned URLs last 1 second to 7 days. |
| `Could not connect` / `NoSuchBucket` on a host like `files.10.0.0.5` | Virtual-hosted style. Use path-style: boto3 `Config(s3={"addressing_style": "path"})`, JavaScript `forcePathStyle: true`. |
| `AccessDenied` without keys | Buckets are private. Sign the request, use a presigned URL, or allow `Principal: "*"` in a bucket policy. |
| Container exits at once | Port taken (MinIO / RustFS also use 9000): create it with `--port`. Run `pskit resources onprem logs files`. |
| Console does not open from another machine | **Listen on** is `127.0.0.1`, or a firewall blocks the port. Use *Check web UI*, `pskit resources onprem tunnel files`, or open the port to your IP. |
| `NotImplemented` | S3 Select, torrents, access points or directory buckets: not supported. |
